Why it exists

Asking an AI to "just rewrite it" doesn't work.

The session that read the original keeps reproducing it, and you end up hunting leftovers by hand. cleanroom puts an actual wall between reading and writing, then checks the result like an auditor would.

Finds every leftover

Token-level winnowing plus copied identifiers, strings, comments, file names, package metadata, README prose, license headers and config keys.

Physically sealed builder

A Docker container that mounts only the approved spec folder and can reach only the model API. No repo, no web, no memory.

Two independent checks

New code must pass its tests, match the old behavior, and stay under the threshold on both winnowing and JPlag.

No leaks back

When a rewrite is too close, the builder hears only "file X, score N". Never the matching lines. Never a diff.

Tamper-evident trail

Every stage, file hash, command and decision goes into a hash-chained log, committed to git at every step.

You stay in charge

License, contracts, patents, distribution, naming, AI-training risk. Plain-language questions, your exact words recorded, no defaults.

How it works

Eight stages. Every one stops if something's wrong.

Run them one at a time, or /cleanroom:run-all to go end to end. It halts at every question for you and every failed check. Click a stage.

Proof, not promises

Copying gets caught. Rewriting passes.

From the included demo on fake repos. The first rewrite cheats by copying the original's structure; both similarity engines reject it. The builder is told only the score, the spec is revised, and attempt two passes.

Install

  
Two commands. No API key required.

  
You need Claude Code, Python 3.10+ and Docker (Docker Desktop on Windows/macOS, Docker Engine on Linux).

Your decisions

  
Six questions no tool should answer for you.

  
Asked one at a time, in plain language. No defaults: skip one and the gate stays shut. Your exact reply is stored with a timestamp, and changing an answer later re-opens the related gates. You can also answer in your own terminal with risk_gate.py ask.

  

    
Gate 1 · hard stop
Did you get the upstream source legitimately?
Rewriting can't fix code you weren't allowed to read.
"no" or "unsure" ends the process

    
Gate 2
Did you agree to other terms (EULA, NDA, employment or client contract)?
A contract can forbid this work whatever copyright says.
"no", or type I accept this risk

    
Gate 3
Do you know of patents on it?
Patents cover ideas, not text. The upstream is also scanned for patent notices.
"no" + nothing found, or I accept this risk

    
Gate 4
Will it be sold, distributed or offered as a service?
Distribution raises the stakes of everything else. "Yes" adds a pre-release checklist.
any answer, recorded

    
Gate 5
What's the new project name?
Trademarks aren't touched by rewriting code. Look-alike names are refused.
a name not close to upstream's

    
Gate 6
Do you understand AI training risk?
The model may have seen the original. Similarity checks reduce that risk; they don't remove it.
type I understand

Honest limits

  
What it can't enforce.

  

    
Not legal advice, and no legal immunity. cleanroom produces evidence that you followed a careful process. AI-run clean rooms haven't been tested in court. Full list with mitigations: LIMITATIONS.md.

  

    
The model may remember the original
Isolation stops it reading the upstream now, not recalling it from training. The two similarity checks are the mitigation.

    
Close paraphrases in specs
The filter catches code, upstream identifiers, long quotes and 8-word copied runs, but not a careful paraphrase of an algorithm. That's why you review every spec.

    
Your Docker setup
CI proves the design on Linux every push. Run the isolation probe on your own machine before the first build, and after Docker updates.

    
Git history still holds the original
Swapping edits the working tree. An optional, separately confirmed step starts fresh history; forks and clones keep the old one.

    
Trademarks, patents, trade secrets, contracts
Clean-room rewriting addresses copyright only. Your answers to the six questions are recorded and linked to each residual risk in the report.

    
Behavior is compared on chosen inputs
Equivalence covers the probe inputs derived from the spec. Add more cases as data before verifying if a module has tricky edges.

  







  
FAQ

  
Questions people ask.

  

    
Do I need an API key?
No. With a Claude Pro, Max, Team or Enterprise plan, run claude setup-token once and set CLEANROOM_BUILDER_OAUTH_TOKEN. An API key works too.

    
Which languages work?
Scanning covers Python, JavaScript/TypeScript, Java, C/C++, C#, Go, Rust, Ruby, PHP, Swift, Kotlin, Scala and shell. Behavior comparison is built in for Python; other languages need a small driver command.

    
The upstream is MIT. Do I need this?
Maybe not. Permissive licenses usually just require keeping the copyright notice. The license gate tells you that and asks whether to continue anyway.

    
What do I get at the end?
CLEANROOM_REPORT.md: license decision, before/after scores from both engines, what was replaced, test and ScanCode results, every decision you made verbatim, and the risks that remain.

    
Can I try it safely first?
Yes. python examples/run_demo.py --dest ./demo builds a fake project pair and runs the whole pipeline without touching your code.

    
How do I contribute or report a hole?
Open an issue on GitHub. Reports of any path that lets upstream content reach the builder, or a gate be bypassed, are the most valuable.
