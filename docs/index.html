Claude Code plugin · open source

Rewrite leftover third-party code. Prove it's gone.

Your project started from someone else's repository, and their code, names and comments are still in there. cleanroom finds what still matches, has it rebuilt from a description by an AI that is physically walled off from the original, checks the result two independent ways, and asks you every question a tool can't answer.

Install in two commands View on GitHub
Not legal advice. cleanroom produces evidence that you followed a careful process. It gives no legal immunity, AI-run clean rooms haven't been tested in court, and the model may have seen the original code during training. Read what it can't enforce before relying on it.

Who it's for

You built your own architecture on top of an upstream open-source project. Now you want to keep your design and replace only the parts that still match upstream, because of its license, because you're going commercial, or because you want a clean codebase. You've tried asking an AI to "rewrite it", and the same session that read the original kept reproducing it.

Finds every leftover

Token-level similarity (k-gram winnowing) plus copied identifiers, strings, comments, file names, package metadata, README text, license headers and config keys.

Builder never sees the original

The rewrite happens in a Docker container that can see only an approved spec folder and can reach only the model API.

You decide the hard parts

License, agreements, patents, distribution, naming and AI-training risk are plain-language questions. Nothing proceeds until you answer.

Two independent checks

Every rewritten module must pass the built-in winnowing scan and JPlag, plus its tests and a behavior comparison with the old code.

Tamper-evident audit trail

Every stage, file hash, command and decision goes into a hash-chained log, committed to git at each step.

Runs on your Claude plan

Works with a Pro, Max, Team or Enterprise subscription. No API key required (an API key works too).

How it works

A classic clean room has two teams with a wall between them: one reads the original and writes a description, the other builds from the description alone. cleanroom does the same with AI agents, and makes the wall physical.

Install

You need Claude Code, Python 3.10+, and Docker (Docker Desktop on Windows and macOS, which needs admin rights and on Windows WSL2; or Docker Engine on Linux).

1. Add the plugin

/plugin marketplace add MndTheNerd/cleanroom
/plugin install cleanroom@cleanroom

2. Pick your options

When you enable the plugin, Claude Code asks you a few questions. Add-ons you select install in the background.

OptionDefaultWhat it's for
JPlag similarity checkeronSecond, independent similarity check (downloads JPlag + a Java 25 runtime, ~150 MB).
ScanCode ToolkitonFinal license scan after the swap (~130 MB).
ScanCode offline sourceemptyA ScanCode .zip or .whl you already have, for slow connections.
Builder credentialsubscriptionUse your Claude plan, or an API key.
Analyzer / builder modelopus / sonnetThey must differ.

Turned an add-on off? The step that needs it stops instead of being skipped. Install it later with /cleanroom:addons.

3. Give the builder its own credential

The builder runs in the container with its own credential, never your main login. With a Claude subscription, in your own terminal:

claude setup-token

Approve in the browser, then set the printed token before starting Claude Code. Never paste it into the chat.

# macOS / Linux
export CLEANROOM_BUILDER_OAUTH_TOKEN=paste-token-here

# Windows PowerShell
$env:CLEANROOM_BUILDER_OAUTH_TOKEN = "paste-token-here"

Builder runs count against your plan's usage limits. Prefer an API key? Set CLEANROOM_BUILDER_API_KEY and pick api_key in the options.

Use it, step by step

Open Claude Code in your project (the "harness") and run /cleanroom:run-all, or go stage by stage. Steps marked you wait for your answer.

  1. /cleanroom:init you

    Asks, one question at a time, for the upstream repo path, languages and test command. Works on a new cleanroom/<date> git branch.

    Detects the upstream license and explains it in plain language. Permissive (MIT/Apache/BSD): you're told attribution may be enough, and asked whether to continue anyway.

  2. /cleanroom:risks you

    Six plain-language questions about access, agreements, patents, distribution, the new name, and AI training risk. See them below.

  3. /cleanroom:scan

    Compares your project with upstream and labels each module original, mixed, tainted or vendored. Add --dry-run to change nothing.

  4. /cleanroom:spec you

    You approve the list of names kept for compatibility (public API, file formats). The analyzer writes a behavior spec per tainted module, the filter rejects leaks, then you read it and type approve spec.

  5. /cleanroom:build

    Runs an isolation probe, then the test-writer and builder in the container, with SHA-256 manifest checks before and after.

  6. /cleanroom:verify

    Tests, behavior comparison with the old module, winnowing and JPlag all have to pass. On failure the spec is revised and you re-approve it (3 tries max).

  7. /cleanroom:swap you

    Shows a one-screen summary. After you type approve swap: backup, swap, delete tainted and vendored files, remove upstream remotes, headers and name, grep for leftovers, run ScanCode.

  8. /cleanroom:report

    Writes CLEANROOM_REPORT.md: license decision, before/after scores from both tools, what was replaced, test results, ScanCode results, every decision you made, and the risks that remain.

The decisions only you can make

No defaults. A skipped question keeps the gate closed. Your exact words are recorded with a timestamp. Changing an answer later re-opens the related gates. You can also answer in your own terminal with risk_gate.py ask.

QuestionWhy it mattersTo continue
Did you get the upstream source legitimately?Rewriting can't fix code you weren't allowed to read."yes". No or unsure is a hard stop.
Did you agree to other terms (EULA, NDA, employment/client contract)?Contracts can forbid this work regardless of copyright."no", or type I accept this risk.
Do you know of patents on it?Patents cover ideas, not text; a rewrite can still infringe. Upstream is scanned for patent notices."no" with nothing found, or type I accept this risk.
Will it be sold, distributed or offered as a service?Distribution raises the stakes of everything else.Any answer; "yes" adds a pre-release checklist.
What's the new project name?Trademarks aren't touched by rewriting code.A name not close to the upstream's.
Do you understand AI training risk?The model may have seen the original; similarity scans reduce, not remove, that risk.Type I understand.

Later gates: approve allowlist, approve spec (per module, and again after any edit), approve swap, and optionally rewrite history.

What it can't enforce

Be clear-eyed about these. The full list with what to do about each is in LIMITATIONS.md.

The model may remember the original from training

Isolation stops it reading the upstream now, not recalling it. The two similarity checks are the mitigation.

Legal status is untested

AI-run clean rooms haven't been tested in court. The report is evidence of process. Get legal review before distributing.

Close paraphrases in specs

The filter catches code, upstream identifiers, long quotes and 8-word copied runs, but not a careful paraphrase of an algorithm. That's why you review every spec.

Your Docker setup

The container design can't be verified until it runs on your machine. Run the isolation probe before your first build, and after Docker updates.

Git history still holds the original

Swapping edits the working tree. An optional, separately confirmed step starts a fresh history; forks and clones keep the old one.

Trademarks, patents, trade secrets, contracts

Clean-room rewriting addresses copyright only. Your answers to the risk questions are recorded and linked in the report.

FAQ

Do I need an API key?

No. With a Claude Pro, Max, Team or Enterprise plan, run claude setup-token once and set CLEANROOM_BUILDER_OAUTH_TOKEN. An API key works too.

Which languages work?

Scanning works on most languages (Python, JavaScript/TypeScript, Java, C/C++, C#, Go, Rust, Ruby, PHP, Swift, Kotlin, Scala, shell). Behavior comparison is built in for Python; other languages need a small driver command.

Can I try it without touching a real project?

Yes: python examples/run_demo.py --dest ./demo builds a fake project pair and runs the whole pipeline.

The upstream is MIT licensed. Do I need this?

Maybe not. Permissive licenses usually only require keeping the copyright notice. The license gate tells you this and asks whether to continue anyway.
